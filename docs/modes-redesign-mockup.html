The hybrid plan

One read-only mode, two write modes. The design keeps the strict read-only safety posture (not the interpretation-permissive one), fails closed on the server, and ships in safe incremental slices. Every choice below traces to a red-team finding.

Backend changes

  • Fail closed. Change chat.py:111 fallback from else "assisted" (write!) to else "research", and make MessageIn.mode a validated Literal. This is the single most important fix — both Red Teams B and D rank it highest: an unknown mode string from a stale PWA currently grants write tools to what the user thinks is read-only.
  • Read-only is a tool-allowlist property (architect.py:2113-2116), not a mode in (...) branch. Update prompts.yaml tool lists and _DEFAULT_MODE_TOOLS (architect.py:40-69) together, or a YAML-load failure silently restores old behavior.
  • Keep medical_reference out of the default read mode. It's an external (MedlinePlus), approval-gated network call (architect.py:504-543). Only the local reference_lookup belongs in read-only. If Full Brain gains it, port analyze's "never diagnose / label general knowledge" clauses into the assisted prompt.
  • Generalize dest routing as an enum. Parametrize next_medical_title → next_capture_title(root, dest) and update sanitize_dest's strip-set (notes.py:199-224) in lockstep with _MED_ROOT. Treat root as a server-side enum (medical|financial), never free-text in a path (traversal). Default root medical to keep test_medical_mode_routes_to_dest_folder green.
  • Rename via aliases, don't orphan. Use the existing _KEY_ALIASES mechanism (prompts.py:76) so a user's saved modes.*.system override survives. Only string-prompt overrides orphan; tool/budget keys read YAML only.
  • Derive the mode list from YAML in validate_agent_config instead of the hard-coded tuple (architect.py:379). It only warns at startup, but test_api.py:692 asserts it's empty.
de-risked No DB migration. All four teams confirmed mode is request-scoped and never persisted — no column on conversations/messages (schema.sql:60-82). The lookalike messages.mode_meta_json stores tool-call steps, not the mode string. So the wire vocabulary can change freely.

What the agents found

Four brainstorm agents proposed; four red teams attacked (one each). Verified findings below.

A · UX / IA

Proposed: 3-segment control replacing the chip; Entry sub-panel; two-axis swipe.

Red Team A killed: two-axis swipe — horizontal swipe was deliberately removed (collides with OS back-gesture, Shell.tsx:188, swipeGesture.ts). Also: "Full Brain is the only write mode" is false — Entry writes too. And a 3-seg control + attach + send won't fit one phone row.

✓ Kept: segmented control on its own row; vertical-only swipe for 3 modes; tap for sub-type.

B · Backend / prompts

Proposed: merge research+analyze keeping analyze's behavior; add reference tools to Full Brain; financial routing-only.

Red Team B caught: P0 safety regression (interpretation-permissive read default); P1 cost regression (14-iter/120k floor); the real read-only guard is the tool allowlist (architect.py:2113), not a mode branch; medical_reference is an external call.

✓ Kept: strict research prompt survives; depth conditional; fail-closed fallback.

C · Entry sub-selector

Proposed: fold entry+medical; Financial v1 = "medical without labs"; dest_root="medical" default.

Red Team C caught: folder-only Financial is a non-feature; lab_parse isn't reusable for statements; dest_root="medical" is a footgun that only "works" because it accidentally satisfies a test.

✓ Kept: structured Financial v1; enum root with generic-safe handling; parsing deferred.

D · Migration / rollout

Proposed: no DB migration; client normalizer; 4-PR incremental rollout.

Red Team D confirmed & hardened: mode-not-in-DB ✓; but fail-open coercion is a privilege risk (fail closed); PWA cache prolongs skew; prompt_overrides + _KEY_ALIASES matter; broaden the grep (api.ts, PLACEHOLDER, CSS accents).

✓ Kept: all of it, plus fail-closed and alias-based override survival.

Decisions for you

The brainstorm resolved most things. These are genuine product calls where I have a recommendation but want your steer before implementation.

1. Read-only Research posture — ✓ DECIDED

Decided: strict by default (keep today's research prompt: facts-only, no clinical/financial interpretation) plus a per-turn "Deep" opt-in that raises the budget for multi-step questions. Deep interpretation otherwise lives in Full Brain. To implement in PR-3: surviving mode keeps the research prompt + a "deep" flag that lifts max_iterations/max_total_tokens toward analyze's ceiling on demand.

2. Default mode on launch — ✓ DECIDED

Decided: Entry on a fresh launch; remember last-selected within a session; relaunch resets to Entry. Implementation: switch the fresh-launch fallback at Chat.tsx:86 from research → entry (sessionStorage already handles in-session memory + relaunch reset).

3. Sub-type scope — ✓ DECIDED

Decided: Folder-only for all three. Medical retains lab-PDF staging; Financial is filing only (no form, no parsing). Structured capture / parsing deferred indefinitely.

4. Reference tools in Full Brain — ✓ DECIDED

Decided: add both reference_lookup (local) and the approval-gated external medical_reference to Full Brain, and port analyze's "never diagnose / label general knowledge" clauses into the assisted prompt so the write-capable mode carries the same safety language. medical_reference stays behind its existing PENDING_EXTERNAL approval gate; neither is added to read-only Research. To implement in PR-3.
